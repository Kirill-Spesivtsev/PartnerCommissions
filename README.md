# PartnerCommissions

Cистема партнёрских отчислений на ASP.NET Core Web API (.NET 8). Партнёры получают комиссии с прибыльных событий своих рефералов по всей цепочке вверх, комиссии периодически выплачиваются на внутренний кошелёк.

## Cтарт

Для старта нужны Docker, Docker compose, .NET 8 SDK.

Локальное развертывание всех сервисов осуществляется с помощью команды: docker compose up -d

Сервисы:
Users API (Swagger) : http://localhost:5001/swagger 
Commissions API (Swagger) : http://localhost:5002/swagger 
Wallets API (Swagger) : http://localhost:5003/swagger
pgAdmin : http://localhost:5050 — `admin@example.com` / `admin`
PostgreSQL : `users-db` :5432, `commissions-db` :5433, `wallets-db` :5434 — `postgres` / `postgres` 

Миграции применяются автоматически при старте сервисов.

В pgAdmin сервер добавляется вручную: host — имя сервиса (`users-db`, `commissions-db`, `wallets-db`), port `5432`.

### Тесты

Запуск тестов: dotnet test PartnerCommissions.sln

## Архитектура

Три микросервиса на Clean Architecture (`Domain` → `Application` → `Infrastructure` → `Api`), у каждого своя база PostgreSQL. Общих проектов и внешних ключей между сервисами нет — связь только по внешним идентификаторам.

- **Users** — пользователи и партнёрское дерево.
- **Commissions** — приём событий, расчёт комиссий, текущая схема расчёта.
- **Wallets** — периодическая выплата комиссий, баланс и история выплат.

Сервисы общаются по HTTP с повторами и circuit breaker. Все эндпоинты — под `api/v1`, ошибки — в формате ProblemDetails, описание API — в Swagger каждого сервиса.

## Расчёт комиссий

Комиссию с события с положительной прибылью получает каждый партнёр в цепочке над владельцем события.

- **Linear:** `L × Profit / 100`.
- **Fibonacci:** `F(L) × Profit / 100`.

Каждая комиссия хранит схему, по которой рассчитана. Смена схемы или дерева действует только на новые события, старые комиссии не пересчитываются.

## Принятые решения

- **Глубина цепочки** — не больше 10 человек, то есть до 9 уровней начисления. Без ограничения Фибоначчи на 11-м уровне раздавал бы больше 100% прибыли.
- **Привязка к партнёру** — `PUT .../referrer`, с проверкой цикла и длины цепочки в транзакции, чтобы параллельные встречные привязки не создали цикл.
- **Прибыль ≤ 0** — событие сохраняется без комиссий. Прибыль принимается с точностью до 2 знаков, суммы комиссий хранятся с 4 знаками.
- **Баланс** — сумма выплаченных комиссий (`SUM`), отдельного поля баланса нет.

## Надёжность

- **Без двойных начислений:** уникальный `ExternalId` события (повтор : 200 с сохранённым результатом), уникальная пара «событие + уровень», первичный ключ `CommissionId` в кошельке, отметка «выплачено» только для ещё не выплаченных.
- **Выплата** — раз в 30 секунд (`Payout:Interval`): забрать невыплаченные, зачислить новые одной транзакцией, отметить выплаченными в Commissions. Любой сбой между шагами безопасно доводится следующим циклом.
- **Отказы:** при недоступности Users приём событий отвечает 503, остальное продолжает работать; Wallets при недоступности Commissions пишет ошибку в лог и повторяет в следующем цикле.
- **Graceful shutdown**, **health checks** (`/health/live`, `/health/ready`), **логи** Serilog, **метрики** Prometheus (`/metrics`) — во всех сервисах.
- **Горизонтальное масштабирование:** сервисы не хранят состояния в памяти, параллельную работу экземпляров защищают ограничения базы данных.
